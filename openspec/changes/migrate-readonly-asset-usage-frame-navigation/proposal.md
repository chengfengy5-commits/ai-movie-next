# Proposal

## Why

素材反查目前只能把用户带到关联章节，无法直接打开对应分镜；即使目标章节正确，用户仍需在其中重新辨认素材命中的镜头。需要沿用当前只读素材快照，为每个可核验的引用提供明确的章节与镜头入口，同时由目标页面重新读取目录和分镜素材，避免依赖旧位置或过期身份。

## What Changes

- 在素材引用反查结果中，为可核验的命中分镜增加“定位对应镜头：<章节> · 镜头<n>”入口，并保留现有“查看对应章节：<标题>”入口。
- 入口仅从当前已读取的章节快照、每个命中 frame 的 `storyboard[0]` 原始 ID 和当前素材目录/分类推导身份；目标页面重新核验章节、分镜与素材身份后才定位。
- 对缺失、重复、跨剧集或已移除的身份停在明确提示，不按标题、位置或相邻项回退；显式重读可重新核对。
- 在工作区接受前，来源 owner、scope 或 ready 读取世代失效会使回调被拒绝；接受后复制的意图只受目标页与工作区的 user/services/series/navigationEpoch scope 及用户显式放弃行为约束，来源自然卸载或旧关闭回调不得撤销它。章节、分镜素材按现有只读流程读取，并保留普通章节导航和返回剧集列表行为。

## Capabilities

### New Capabilities
- `readonly-asset-usage-frame-navigation`: 从素材引用反查结果只读定位到经目标快照再次核验的章节分镜。

### Modified Capabilities
无。

## Impact

- 影响 React 工作台中的素材反查面板、工作区导航状态和章节浏览页，以及相应局部投影与前端测试。
- 复用现有章节目录与章节分镜素材只读读取，不新增 API、DTO、service 方法、依赖、fixture 端点或演示素材。
- 不改既有素材引用投影契约；不读取或显示原始素材 URL，不新增媒体 API、媒体节点或主动媒体读取逻辑；既有章节页安全 loopback 图片行为保持不变。不增加章节/分镜写入、播放、导出或锁操作。
