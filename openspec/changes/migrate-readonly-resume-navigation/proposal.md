# Proposal

## Why

个人制作记录已能核对保存的续作位置，但用户仍需手动在分镜列表中寻找镜头。增加明确的本地定位操作，让用户回到已核对的当前章节镜头，同时保留只读迁移边界。

## What Changes

- 在个人制作记录的有效续作位置旁增加“定位到续作镜头”按钮；仅用户点击时定位，不在打开、读取成功或重读后自动跳转。
- 复用已加载的章节、资产和个人记录投影，定位并聚焦当前章节中已核对的唯一镜头，提供可见位置反馈与键盘可访问的焦点。
- 读取中、读取错误、没有续作位置、失效身份、媒体快照无法核对或上下文变化时不开放定位；旧按钮和旧响应不能定位新用户、新章节或新服务上下文。
- 点击定位不新增业务请求、设置续作位置、修改记录、触发生成或加载新媒体；保持个人制作记录与粗剪互斥及既有返回列表行为。
- 增加针对身份和生命周期风险的自动验证，以及 root 的桌面、390px 和键盘真实浏览器验收。

## Capabilities

### New Capabilities

- `readonly-resume-navigation`: 根据当前已核对个人记录，在已加载章节中进行显式、安全且可访问的本地镜头定位。

### Modified Capabilities

无。主规格库为空；本切片扩展当前页面行为，前七 change 的规划与历史验收保持不变。

## Impact

仅影响 React 个人制作记录面板、章节浏览器、局部样式与相关测试和当前文档。不新增接口、依赖或来源复制；隔离 fixture 的十二条业务接口白名单保持不变。

冻结来源为 `23403806898550a7668a6ee7c0c457315655c39b`。旧 `js/episode.js:10120-10161` 的续作导航核对当前会话、已加载章节和唯一稳定身份后选择分镜。新实现使用现有更严格的个人记录投影核对结果，仅移动页面焦点，不开放编辑、锁、写入、播放、生成、导出或任务操作。新库独立开发，不启动真实 FastAPI、数据库、Worker、队列、R2、付费或生产媒体链路，不提交、推送或部署。固定 GPT-5.6 Sol/xhigh 的 Grillme 离线补审单列待办。
