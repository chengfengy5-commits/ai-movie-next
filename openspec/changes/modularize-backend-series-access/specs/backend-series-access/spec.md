# Spec Delta

## Purpose

为隔离的新后端提供基于当前数据库剧集、团队成员及认领记录的访问判断。保留原有作者与团队认领限制的优先级和中文失败原因，并可接入已有个人粗剪请求，避免以实验默认允许策略代替真实业务授权。

## ADDED Requirements

### Requirement: 剧集及认领限制优先级

系统 SHALL 先查找当前剧集；缺失返回404及“剧集不存在”。存在且团队与他人认领信息均为真值时，系统 MUST 先执行认领限制，再判断作者及普通成员访问。作者身份不能绕过他人的认领限制。

#### Scenario: 剧集不存在
- **WHEN** 可信身份访问数据库不存在的剧集
- **THEN** 返回404及“剧集不存在”，不查询团队成员或认领人

#### Scenario: 作者被他人认领限制
- **WHEN** 团队剧集的作者不是当前认领人，且没有可进入认领剧集的成员权限
- **THEN** 返回403和当前认领人的用户名原因，不因作者身份放行

### Requirement: 认领准入与最终访问资格

系统 SHALL 对团队他人认领只允许 membership.role 为 owner 的成员，或有效权限列表含 enter_claimed_series 的成员通过认领限制。系统 MUST 随后要求作者归属或团队成员资格；认领者本人只跳过认领限制，不独立取得最终资格。不存在额外超级用户、Team.owner_id 或 admin 角色放行规则。

#### Scenario: 认领者不是作者且已不在团队
- **WHEN** claimed_by 等于当前可信身份，但此人不是剧集作者且无该团队成员记录
- **THEN** 返回403及“无权访问该剧集”

#### Scenario: 队长或有权限的成员
- **WHEN** 他人认领且当前团队成员的 role 为 owner，或有效权限含 enter_claimed_series
- **THEN** 通过访问；permission 不额外要求 admin 角色

#### Scenario: 无认领或个人剧集
- **WHEN** 无团队、无认领或认领属于本人
- **THEN** 作者可访问；非作者仅在属于当前剧集团队时可访问，其他情况返回403及“无权访问该剧集”

### Requirement: 权限 JSON 与既有失败信息

系统 SHALL 保留已知权限键过滤和原始 JSON 列表语义；空、非法JSON、非列表及列表中任一不可hash元素导致整个权限集合为空。只有精确字符串 enter_claimed_series 授权，不修剪、不按名称猜测、不增加角色限制。认领拒绝 MUST 使用“该剧集已由「{name}」负责制作，暂不可进入”；name 取当前认领用户的 username，用户缺失取空字符串。

#### Scenario: 混合非法权限列表
- **WHEN** 列表同时含有效 enter_claimed_series 与不可hash元素
- **THEN** 不因前面的有效键放行，保留整体空权限行为

#### Scenario: 认领用户缺失或姓名变化
- **WHEN** 因他人认领拒绝访问
- **THEN** 每次取当前数据库名字，缺用户使用空名，不缓存旧用户名

### Requirement: 显式组合及请求数据隔离

系统 SHALL 仅从可信身份端口取得 user_id，并在调用方传入的同一请求 Session 内完成剧集、成员和用户名判断。策略 MUST 不创建、提交、回滚或关闭 Session，不写入业务记录或授予编辑锁，不增加 HTTP 方法；已有粗剪在查章后、源内容/素材及本人草稿查询前执行策略。

#### Scenario: 原粗剪端口明确接入
- **WHEN** 调用方显式把本能力接入已有 GET/PUT 粗剪端口，并提供可信身份和Session factory
- **THEN** 数据库访问规则实际控制请求；未授权不读取源素材和本人草稿，不保存任何私人草稿

#### Scenario: 当前成员资格变化
- **WHEN** 此前仅凭成员资格访问且成员记录被移除；或在他人认领保持不变时，此前仅凭 enter_claimed_series 通过认领限制且该权限被撤销、没有 owner 资格
- **THEN** 下一次独立请求读取当前记录并拒绝，不复用旧决定；仍具作者资格的未认领剧集，以及仍具成员资格的未认领剧集，不因这项特殊权限撤销而拒绝

#### Scenario: 省略安全接线
- **WHEN** 原粗剪工厂缺少身份、Session或访问策略端口
- **THEN** 保持第22批503和零Session行为，不自动安装此策略或默认允许

### Requirement: 隔离且可验证的模块

系统 MUST 在独立新后端模块中实现访问判断，保留既有代码/配置及所有历史产物；生产导入和构造不得读取环境、创建 Engine/schema/Session 或导入旧 app。测试与验收只能使用自有临时数据库，合成身份与真实数据库访问策略的证据 MUST 分别标明，不将其称为真实JWT、会员或PG并发验收。

#### Scenario: 纯层与冷启动
- **WHEN** 导入所有新模块并构造策略及原应用
- **THEN** 没有环境、数据库连接、建表或旧服务启动副作用，纯规则和应用层不依赖框架
