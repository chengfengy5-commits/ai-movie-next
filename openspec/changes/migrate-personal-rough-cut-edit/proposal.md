# Proposal

## Why

现有 React 工作台只能查看本人粗剪投影，不能调整镜头顺序、纳入状态或保存编排；用户仍需返回旧页面完成这条业务链。第 21 切片将这一完整写入链迁移到隔离前端，以已有 FastAPI 契约为依据，继续保留旧库和线上服务。

## What Changes

- 在“我的粗剪草稿”中提供显式编辑、按纳入状态分组的上下移、纳入/排除、取消编辑与保存。上下移沿旧页面的同组交换规则；保留当前 canonical 草稿的只读筛选和镜头定位。
- 增加可选 `savePersonalRoughCut` 服务能力，调用既有粗剪路径的 PUT；严格提交本人同章 revision 和完整当前稳定镜头集合，不保存媒体、便签或认可状态。
- 用独立编辑器、纯规则模块和编辑生命周期模块管理草稿、同步写门禁、旧回调及迟到请求，避免把写入状态全部堆入原只读面板。拒绝/未知结果保留意图，仅显式 GET 成功后允许重新决策。
- demo 与 loopback fixture 提供本人章节内存保存、CAS、两账号隔离和拒绝/未知结果模式，测试完整业务链和既有读取/导航回归。
- 客户端明确支持合法 API 的首次显式保存（包括空章）及待安排/失效旧记录的显式全量提交；这些是本批新入口，不冒称旧 JavaScript 已提供相同行为。

## Capabilities

### New Capabilities

- `personal-rough-cut-edit`: 完整个人粗剪编排、纳入状态及显式保存，包含身份核对、版本并发、失败恢复与用户隔离。

### Modified Capabilities

无。主规格清单当前为空；前二十个 change 及其验收历史保持原文。

## Impact

- 仅改 `haoai-next` 的粗剪前端、粗剪 DTO 的 EOF 追加更新解析、services、fixture 和必要样式；新增粗剪编辑模块及对应测试。旧读取/parser、便签/续作功能、章节/父工作台、全部旧测试/样本/依赖保持冻结。
- 新增被迁移的业务方法模式为 `PUT /api/chapters/{chapter_id}/rough-cut`，与原 GET 同路径；业务方法白名单由 13 种变为 14 种，不新增服务器 endpoint。
- 根验证最终冻结代码、桌面/移动/键盘操作、真实 loopback HTTP 和全量旧回归；指定 GPT-5.6 Sol/xhigh Grillme 仍为离线独立待办。
- 本批不迁移播放/导出、生成、任务/收费、团队/账号管理，不运行真实 FastAPI、PostgreSQL、Worker、队列或 R2，不提交/推送/部署。后端模块化仍未落地；本批完成后应优先形成真实后端模块边界，不能把 fixture 或前端分模块记为后端重构完成。
