# Proposal

## Why

当前素材库能查看素材文字，却不能直接知道某个角色、场景或道具出现在哪些镜头。第十批在现有只读目录上补充关联镜头文字反查，减少用户逐章查找的操作。

## What Changes

- 为素材卡片提供显式“查看关联镜头”入口，仅在用户打开时读取当前剧集的既有章节列表。
- 按当前分类与素材原始 ID 精确匹配章节引用，保留章节响应顺序和镜头位置；同镜头重复引用以一次镜头行和引用次数表示。
- 展示章节标题、镜头位置、镜头文字及原文；空结果、无法核对的引用、错误与显式重读有独立反馈。
- 一次只打开一个素材的反查面板；换分类、目录重读、换素材、离开或会话变化使旧读取失效，关闭重开重新读取。
- 保持现有十二条业务接口、演示和 fixture 样本、前九批历史、来源复制 exact-five 及运行隔离边界。

## Capabilities

### New Capabilities

- `readonly-asset-frame-usage`：剧集素材按分类和稳定原始身份反查已读取章节中的镜头文字。

### Modified Capabilities

无；既有能力历史规格不回写，本批记录新的交互契约。

## Impact

涉及 `frontend/src/features/assets/` 的局部投影、反查面板、目录集成、相应 UI/会话回归与样式。复用现有 `listChapters`，不增加 DTO、服务方法、端点或依赖；不读取分镜图片、个人记录或粗剪，不增加媒体、跳转、写入和生成入口。

仅在隔离 `haoai-next` 实现与本地 demo/loopback fixture 验收。旧 checkout、真实 FastAPI/数据库/Worker/R2/付费任务和生产保持隔离，不提交、推送或部署。Grillme 固定 GPT-5.6 Sol/xhigh 离线待审单列，不替代本地开发。
