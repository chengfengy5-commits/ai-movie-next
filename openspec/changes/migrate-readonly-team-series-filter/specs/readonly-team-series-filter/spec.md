# Spec Delta

## Purpose

让当前用户在工作台的团队剧集分类中按所属团队查找剧集，保留暂无剧集的团队选项、原有剧集权限和展示状态，并使团队目录请求在隐藏视图、刷新及登录会话变化时保持隔离。

## ADDED Requirements

### Requirement: 当前用户团队目录契约

系统 SHALL 仅通过当前 Bearer 会话的 `GET /api/teams/my` 读取团队目录，不传客户端用户、团队或分页参数。响应 MUST 为数组，每项 MUST 自有六个必备字段：非空字符串 `id/owner_id`，允许空字符串的 `name/my_role`，有效 ISO 日期字符串 `created_at`，非负安全整数 `member_count`；缺字段、null、错误类型、非法日期、重复 id 或外层结构错误 MUST 呈现无效响应，不能变为空名单。id MUST 不要求 UUID，未知角色 MUST 保留，字段不构成前端权限授予。

#### Scenario: 完整但历史化的目录
- **WHEN** 返回按任意顺序排列的同名团队、空名称、未知角色及 id 为 `all` 或其他非 UUID 的合法记录
- **THEN** 系统保留全部记录和响应顺序，空名称显示“团队”，团队身份不按名称合并且不与“全部团队”混淆

#### Scenario: 空名单与坏响应
- **WHEN** 返回合法 `[]` 或缺字段、重复 id、坏类型等无效响应
- **THEN** 前者呈现“暂无所属团队”，后者呈现可显式重试的错误，两者均不删除现有剧集

### Requirement: 团队筛选保留剧集来源和权限

系统 SHALL 仅在“团队剧集”分类展示“全部团队”和目录中的具体团队选项，即使目录有零个或一个团队、或某团队暂无剧集。全部团队 MUST 沿用现有 `team_id` 有值的分类语义；具体团队 MUST 对现有剧集列表按 `team_id` 精确匹配，在切片展示前完成筛选，保留服务端顺序。系统 MUST 不将目录与剧集做授权交集，不按名称合并，不调用团队剧集分页接口，不改写 `user_id/claimed_by/can_enter` 或卡片进入权限。

#### Scenario: 名单之外的本人共享剧集
- **WHEN** `/api/series` 包含本人持有且共享到未在团队目录返回的团队的剧集
- **THEN** 它仍出现在“全部团队”和原有“我创建的”分类，后端 `can_enter` 仍决定只读进入入口

#### Scenario: 无剧集的所属团队
- **WHEN** 用户选择一个目录已返回但当前列表无剧集的团队
- **THEN** 选项保持选中并显示“该团队暂无剧集”，不当作请求失败、不发额外 GET

### Requirement: 分类与递增展示状态

系统 SHALL 保留四个主分类及每次增加 20 条的展示方式。实际切换主分类或具体团队 MUST 将展示数重置为 20；重复点击同一分类或选择同一团队 MUST 不重置数量、不触发目录 GET；离开“团队剧集”分类 MUST 清除具体团队选择。进入章节、素材或任务视图后再返回列表 MUST 保留主分类、已选团队、已展示数量和当前会话内成功目录快照。

#### Scenario: 先筛选后展示与返回
- **WHEN** 某团队有 45 个合法剧集，用户从 20 条加载至 40 条并进入其他视图后返回
- **THEN** 返回仍显示该团队的 40 条，切换团队或主分类后从 20 条开始

### Requirement: 按需读取与隐藏隔离

系统 SHALL 仅在用户显式进入可见的“团队剧集”分类且没有成功快照、或显式重读/重试时读取目录，不在登录、其他分类或隐藏列表预取，不轮询。离开团队分类、列表变为 hidden/inert、卸载、退出或会话切换 MUST 中止在途请求并使其成功、错误和401失效。返回团队分类时，已有成功快照 MUST 直接恢复；没有快照且上次仅因离开被中止 MUST 发起新的目录 GET；实际错误 MUST 等待用户显式重试，不自动重试。

#### Scenario: 首次读取中离开再返回
- **WHEN** 团队请求尚未成功，用户进入任务页后返回原团队分类
- **THEN** 原请求失效，返回发起一个新请求；原请求随后成功或401均不能改写新状态或退出当前会话

#### Scenario: 已加载后离开再返回
- **WHEN** 团队目录已成功，用户进入章节、素材或任务视图后返回
- **THEN** 原成功快照和筛选/展示状态直接恢复，不重复读取目录

### Requirement: 显式重读与选中团队失效

系统 SHALL 在 loading 时仍允许显式“重新读取团队”，取消并替换在途目录请求，不补发剧集 GET。重读期间 SHALL 保留本会话内上次成功快照及选择，同时明确显示读取状态或错误，不使用持久化旧缓存静默兜底。成功响应 MUST 按应用响应时的当前选择判断；若仍包含当前已选 id MUST 保留选择与展示数；若不再包含该 id MUST 原子切回“全部团队”、重置展示数为20并说明团队名单已变化。

#### Scenario: 所选团队不再返回
- **WHEN** 用户重读后目录不再包含此前选中的团队
- **THEN** 可见选项与实际过滤同时改为“全部团队”，展示数为20，说明名单变化且不追加其他业务请求

#### Scenario: 重读竞争
- **WHEN** 用户在请求未完成时再次重读，新请求成功后旧请求才成功或401
- **THEN** 只有新请求生效，旧响应不能覆盖目录、重新选择旧团队或清理登录

### Requirement: 错误与会话隐私

系统 SHALL 将团队目录 loading、合法空名单、所选团队无剧集和读取错误分开呈现，并保留已有剧集。仅有效当前401 MUST 执行现有退出行为；会员403、其他403、404、422、5xx、超时、网络和无效响应 MUST 保留登录并允许显式重试。成功目录缓存 MUST 仅存在当前用户会话及页面内存，不跨用户、服务实例或持久化存储复用；用户或服务实例变化后的首次呈现 MUST 不显示旧团队名称、选择或错误；退出、新登录和上下文变化后旧响应 MUST 无效。

#### Scenario: 当前读取失败
- **WHEN** 当前目录读取返回会员403、其他非401错误或无效响应
- **THEN** 系统显示相应错误，保留会话及剧集；有成功快照时明确它是上次成功结果，没有快照时不虚构团队选项

#### Scenario: 退出后新用户登录
- **WHEN** 用户退出并以另一用户登录，旧用户目录请求随后成功或401
- **THEN** 新用户只能读取自己的目录，旧目录和旧401均不能影响其筛选、任务页或登录状态

### Requirement: 只读迁移与隔离验收

系统 SHALL 将本切片新增调用限制为 `GET /api/teams/my`，业务接口白名单总计十一条（十 GET 与一个 POST 登录）；团队选择不触发写入、详情、邀请、角色管理、分享、认领、锁、生成、队列或媒体。默认 demo MUST 无业务网络请求；API 验收 MUST 仅连接隔离 loopback fixture。记录 MUST 区分冻结源码核对、本地自动测试、真实浏览器、未运行的真实 FastAPI/数据库/生产及离线 Grillme；不得将 GET handler 无显式写入称为认证链无数据库维护。

#### Scenario: 请求边界
- **WHEN** 用户登录、打开团队分类、切换团队、重读并往返现有只读视图
- **THEN** demo 无业务请求，API 只出现已批准接口和所需本地合成图片；来源复制仍为 exact-five，不连接旧服务或付费资源
