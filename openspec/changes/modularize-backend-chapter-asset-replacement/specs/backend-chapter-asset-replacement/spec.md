# Spec Delta

## Purpose

为章节中的角色、场景或道具引用提供兼容的素材替换流程，并明确权限、内容变更、媒体协调、孤儿清理与两阶段失败后的可观察结果。

## ADDED Requirements

### Requirement: 章节素材替换请求与错误优先级
系统 MUST 提供 `POST /api/chapters/{chapter_id}/replace-asset`，接受必填普通字符串 `old_asset_id`、`new_asset_id` 和 `asset_type`。请求模型 MUST 保持标准类型校验和额外字段忽略，不增加去空格、长度、UUID 或枚举约束。认证与活动会员检查 MUST 使用现有认证行为；处理器 MUST 按旧顺序校验旧新 ID 相同、素材类型、章节存在、普通剧集访问权限、新素材属于同一剧集且类别匹配、章节内容格式及旧引用是否存在。

#### Scenario: 请求模型校验与额外字段
- **WHEN** 请求缺少必填字段或字段类型不符合普通字符串要求
- **THEN** 系统按标准请求校验返回 422，且不会因额外字段而拒绝请求

#### Scenario: 处理器错误优先级
- **WHEN** 请求同时包含旧新 ID 相同、无效类别、缺失章节、无权访问或新素材不存在中的多个错误
- **THEN** 系统按既定顺序返回最先命中的错误；类别仅接受 character、scene 或 prop，且不得新增认领、锁刷新或并发 CAS 规则

#### Scenario: 章节内容异常
- **WHEN** 章节不存在、剧集访问失败、新素材不属于同剧且同类别、内容格式无效或没有任何镜头引用旧素材
- **THEN** 系统分别保持既有 404、访问拒绝或 400 行为，不创建素材记录

### Requirement: 按镜头保留章节内容并替换引用
系统 MUST 只检查对象帧中与请求类别对应的列表。系统 MUST 保留帧顺序、重复值、非对象帧、其他类别、分镜/预览/文本及未知字段。若新 ID 已在目标类别列表中，系统 MUST 删除该帧中全部旧 ID 并保留已有新 ID 及其重复；否则 MUST 将每个旧 ID 替换为新 ID。响应中的替换数量 MUST 按受影响镜头计数，而非旧 ID 出现次数。成功写入的章节内容 MUST 使用兼容的非 ASCII JSON 序列化形式。

#### Scenario: 替换多个镜头和重复引用
- **WHEN** 多个对象帧在目标类别中含旧 ID，且其中一个帧已有重复的新 ID
- **THEN** 系统只改目标类别，按既定规则删除或替换旧 ID，保留其他内容，并按受影响帧数生成响应数量

#### Scenario: 保留非对象帧及未知字段
- **WHEN** 章节列表还包含非对象成员、其他类别引用和未知字段
- **THEN** 系统保留这些成员及字段，不规范化或重排未参与替换的数据

#### Scenario: 内容格式分支
- **WHEN** 数据库内容为空或假值、JSON 解码失败、解码结果不是列表，或 truthy 的素材引用无法加入集合
- **THEN** 系统按兼容规则分别视为空引用、返回格式错误，或在后续扫描阶段保留原有失败行为

### Requirement: 替换内容时协调个人媒体状态
系统 MUST 在任何章节内容写入前，使用同一个业务 Session 调用现有个人媒体协调规则。协调器 MUST 读取写入时的持久化章节基础内容，并允许既有规则对媒体状态和个人认可做必要维护；系统 MUST NOT 将类别素材引用替换扩展为分镜媒体身份变更，也 MUST NOT 承诺协调器永不写入媒体或个人记录。阶段一的章节 UPDATE MUST 只以章节主键定位，并且只写 content 与 updated_at；影响行数不是 1 时 MUST 返回通用 500 并回滚本阶段，不得改为 409，也不得追加 expected-content 条件或其他更新谓词。

#### Scenario: 同步媒体状态
- **WHEN** 替换章节内容并且个人媒体状态需要依据既有规则维护
- **THEN** 系统先完成同一 Session 内的媒体协调，再写入章节内容；媒体状态和个人记录的结果遵循既有协调规则

#### Scenario: 不改变分镜媒体身份
- **WHEN** 仅替换角色、场景或道具类别的素材引用，且分镜首项身份未变化
- **THEN** 系统不把该类别替换伪装成分镜图片身份变化或新增素材关联

### Requirement: 分阶段清理同剧孤儿素材
阶段一提交成功后，系统 MUST 在同一 Session 的新事务中按章节主键真实重新读取章节，并以该次读取到的当前 series_id 扫描该剧全部章节的当前内容，收集全部三类素材引用。系统 MUST NOT 沿用首次读取的章节快照或首次 series_id。初始章节查询未命中 MUST 保持 404；阶段一提交后的章节重读未命中 MUST 返回通用 500。若 series_id 在两个阶段之间变化，系统 MUST 按重读到的值扫描和选取候选素材，不追加重新授权或剧集一致性门槛。坏 JSON 或非列表按旧扫描行为忽略，非对象帧跳过；无法哈希的 truthy 引用保留原有失败行为。候选素材 MUST 先按当前剧集、请求类别和旧素材 ID 查询，随后仅按已选中行的主键执行 DELETE，不得追加剧集或元数据条件。未版本化素材 DELETE 影响零行时 MUST 保留旧 ORM warning 语义并继续阶段二提交；即使候选查询没有行或旧 ID 仍被其他章节引用，阶段二仍 MUST 独立提交。

#### Scenario: 阶段一后按主键重新读取章节

- **WHEN** 阶段一提交后章节仍存在，或在该次重读前已被其他事务删除

- **THEN** 系统在同一 Session 的新事务中按主键读取并使用当时的 series_id；若重读缺行则返回通用 500，初始查询缺行仍为既有 404

#### Scenario: 其他章节仍引用旧素材
- **WHEN** 替换后同一剧集的另一章节仍引用该类别的旧素材
- **THEN** 系统保留旧素材；其他类别、其他剧集的同 ID 素材及无关孤儿素材均不受影响

#### Scenario: 第二阶段没有可删除行
- **WHEN** 第一阶段成功，但旧素材行不存在或仍被引用
- **THEN** 系统仍完成孤儿清理阶段的独立提交，并返回真实章节和新素材读取结果

### Requirement: 两阶段失败与提交后读取结果
第一阶段提交前发生错误时，系统 MUST 回滚该阶段已经完成的章节和媒体数据库写入。第二阶段扫描、删除或提交失败时，系统 MUST 返回通用失败且不得自动重试；已经成功提交的第一阶段保持持久化。若任一阶段的提交在数据可能已经持久化后返回确认错误，系统 MUST 将结果视为未知并返回通用 500，不得自动重试；显式 GET MUST 反映实际持久状态，回滚不能撤销已经完成的前一阶段提交。提交后章节或新素材名称读取失败时，系统 MUST NOT 返回成功响应，也 MUST NOT 自动重放替换。阶段二提交后，系统 MUST 在同一 Session 中先按章节主键真实刷新章节，再按原新素材主键读取名称或标题，不追加剧集过滤或重新授权。成功响应 MUST 仅为 {"message":"已替换 N 处分镜，使用 X"}；角色/道具 name 为假值时展示名 MUST 为 未知，场景空 title MUST 保持空字符串。

#### Scenario: 第一阶段提交前失败
- **WHEN** 第一阶段完成媒体协调或章节写入后、提交前发生异常
- **THEN** 第一阶段的章节、媒体状态和个人记录写入整体回滚

#### Scenario: 第二阶段失败
- **WHEN** 第一阶段已提交，随后孤儿扫描或清理阶段失败
- **THEN** 请求失败且不自动重试；新读取可观察到章节替换已持久化，而第二阶段删除未被错误描述为成功

#### Scenario: 提交后读取失败
- **WHEN** 提交成功后章节刷新或新素材名称/标题读取失败
- **THEN** 请求返回失败且不自动重放；若提交已经生效，后续显式读取反映该持久化状态

### Requirement: 仅使用既有权限和本地数据库行为
系统 MUST 使用可信认证身份与现有同剧访问策略，不信任请求身份字段。该流程 MUST NOT 新增数据库 schema、迁移、provider、存储、生成、队列或金融写入，也 MUST NOT 把模块登记或 SQLite 验收描述为真实 PostgreSQL 并发验证。

#### Scenario: 未授权身份
- **WHEN** 活动会员或普通剧集访问校验拒绝请求
- **THEN** 系统返回既有认证/授权错误，且不执行素材查询之后的章节或素材写入

#### Scenario: 外部系统边界
- **WHEN** 调用章节素材替换流程
- **THEN** 系统仅执行该流程需要的数据库与日志行为，不调用文件存储、生成供应商、Worker 或队列
