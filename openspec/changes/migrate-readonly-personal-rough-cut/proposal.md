# Proposal

## Why

前六切片已能查看章节、个人制作记录和个人任务，个人粗剪草稿仍缺少迁移入口。增加当前章节的本人草稿只读视图，让用户核对已保存的编排顺序、纳入状态与新增或失效引用，同时保持隔离开发和无媒体消费的边界。

## What Changes

- 在已选章节中增加“查看我的粗剪草稿”显式入口与可关闭的只读面板；默认不预取，打开或显式重新读取才请求。
- 仅新增 GET `/api/chapters/{chapter_id}/rough-cut`，按当前登录用户读取；保留服务端返回顺序，展示草稿版本、读取时章节位置、正文、纳入/排除、待安排及不可用原因。
- 区分“未保存的初始投影”“已保存草稿的当前投影”和合法空列表；失效旧引用仅显示条数，重复引用按响应条数保留。
- 原始素材 ID 和视频 URL 不进入可见正文、DOM 属性、日志、链接或媒体元素。“已纳入”不代表可播放、可导出或已认可；正文与视频引用来自读取时的章节，未被冻结在草稿中。
- 关闭、切章、章节或原图重新读取、离开章节页、退出及切换用户/服务实例使面板与旧响应失效；当前有效 401 使会话失效，其余读取错误保留会话并允许显式重读。
- 增加独立无网络 demo 草稿生成器、隔离 HTTP fixture 和风险对应的自动/真实浏览器验收；不改现有 24 剧集及章节样本，不扩展来源复制名单。

## Capabilities

### New Capabilities

- `readonly-personal-rough-cut`: 当前章节个人粗剪草稿的严格读取契约、只读呈现、私有生命周期及隔离验收。

### Modified Capabilities

无。主规格库为空；本能力接入现有章节页，前六 change 的历史规划与验收记录保持原样。

## Impact

影响 React 章节页、WorkspaceServices、独立 DTO/demo、隔离 fixture 及相关测试；不增加依赖、不实现旧后端。业务接口白名单从 11 种变为 12 种（11 GET + 登录 POST），只增加上述 GET。

冻结来源为 `23403806898550a7668a6ee7c0c457315655c39b`。旧 GET 无 `response_model`，草稿查询与合并在该路由中仅查询/内存投影；认证链可能维护 session 并提交，故不承诺纯数据库读取。无真实 FastAPI、数据库、Worker、队列、R2、付费或远端媒体调用；不实现保存、排序编辑、纳入切换、播放、下载、导出、认可、锁或生成。exact-five 复制白名单不变，无提交、推送或部署。固定 GPT-5.6 Sol/xhigh 的 Grillme 离线待办独立保留，不由本次规划或本地验收替代。
