# Design

## Context

参见 [proposal.md](./proposal.md) 的动机和 [specs/readonly-asset-usage-chapter-navigation/spec.md](./specs/readonly-asset-usage-chapter-navigation/spec.md) 的外部行为约束。素材反查投影目前保留章节显示位置与标题，但不携带章节身份；面板自身持有产生该投影的原始章节响应。`Workspace` 在素材页与章节页间切换时会卸载来源面板，`ChapterBrowser` 当前会重新读取章节并默认选择首项。目标导航必须使用来源快照中的章节 ID，并在目标页重新验证，不能复用旧的按索引选择逻辑。

## Goals / Non-Goals

**Goals:**

- 用一次性、可核对的导航意图把已验证的素材章节结果交给目标章节页。
- 隔离来源与目标页的用户、服务、剧集、读取世代和迟到响应，保留现有章节页普通首章流程及返回列表体验。
- 在目标不存在或无法唯一匹配时停留在无选中章节状态，允许显式重读或用户主动放弃目标。

**Non-Goals:**

- 不增加 API、DTO、services 方法、依赖、fixture 端点或合成素材；不改第十批的 `assetFrameUsage.ts` 和 `assetFrameUsage.test.ts`。
- 不按帧位置导航，不定位具体分镜，不复用旧聊天/历史选择器，不新增写入、自动刷新或媒体访问。
- 不增加返回素材页或自动恢复来源面板的流程。

## Decisions

### 从同一来源快照生成不可变的导航意图

素材反查面板继续调用现有 `listChapters` 和投影函数。面板仅在 ready 响应仍属于当前完整来源 owner、读取世代和结果时显示每个命中章节的“查看对应章节：<标题>”按钮。投影的 `position` 只用于在**同一份已验证响应**中找到其原始 `Chapter`；按钮目标随后绑定原始 `id` 与 `series_id`，并要求 ID 在快照中唯一、非空且与剧集一致。父级只有在剧集 `can_enter === true` 时接受点击。标题、帧位置和数组顺序都不作为目标页身份。

点击回调先由来源面板验证 owner、快照、请求世代和当前目录，再由工作区验证当前用户、服务、剧集、素材视图和 `can_enter`。工作区接受后复制 `{ userId, services, seriesId, chapterId, navigationEpoch }`；复制后的意图不再依赖来源面板的 `isCurrent`，因此来源卸载不会取消它。若 userId、services 实例或 seriesId 改变，工作区永久取消该意图，不得将它重新解释到新范围。来源的旧按钮或旧关闭回调只能作用于原 owner，不能改写新意图。

**备选方案：**让目标章节页接收投影位置或标题并寻找相应章节。拒绝该方案，因为目录排序、同名章节或快照更新都可能把用户带到错误章节。

### 在目标章节页先核对，再选择；只有唯一匹配才消费意图

`ChapterBrowser` 收到导航意图后仍使用现有 `listChapters(seriesId, signal)` 读取新目录。加载开始时清空并隐藏旧章节和素材结果。成功后按原始 ID 与当前 seriesId 过滤：恰好一个匹配项时直接选中该章节；不能先执行默认首章选择。现有选章 effect 随后只为此目标读取一次分镜素材，空内容沿用既有空数组分支，不请求素材。

如果 ID 缺失、重复或匹配项不属于当前剧集，则保持 `selectedChapterId = null`、不运行素材读取 effect，并显示无法确认目标的提示。工作区保留该意图供章节页显式重读；重读必须再按同一 ID 核对，不能退回首章。只有唯一目标实际被选中时，工作区才标记该世代已消费。之后用户手动选择其他章节时也明确放弃目标；后续普通刷新不再应用它。

若没有待处理导航意图，章节页保留现有默认首章行为。显式返回列表、离开目标页或身份/剧集范围改变时取消未消费意图。目录读取非 401 失败保留意图并显示重试；当前有效 401 沿用现有登出流程。

**备选方案：**读取新目录后先选择首章、再异步切换到目标。拒绝该方案，因为它会短暂展示错误章节并触发多余的章节素材 GET。

### 把目标身份与完整页面作用域及请求世代绑定

工作区导航意图带有单调递增的 `navigationEpoch`，防止旧目标、旧消费通知或 ABA（A→B→A）重用。`ChapterBrowser` 的章节请求捕获 userId、services 实例、seriesId、导航世代和请求世代；只有全部仍当前的响应才能设置章节、选中目标、消费意图或处理 401。范围失配在首个 layout commit 即隐藏旧章节/目标并清理章节素材缓存；仅 effect cleanup/abort 不足以保护忽略 abort 的 Promise。

章节读取的 effect 使用当前标记与请求世代保护迟到响应，并避免 StrictMode setup/cleanup 探测产生重复真实读取。显式重读立即推进请求世代和清空旧页面结果后启动新 GET。已消费意图不进入该后续 GET，因此刷新或手动切章不会把用户再次导航到旧目标。

**备选方案：**只依赖 AbortController 或组件卸载。拒绝该方案，因为某些响应可能无视取消继续完成，迟到成功可能覆盖新页面，迟到 401 也可能注销新用户。

### 保持现有工作台返回与素材读取边界

工作区从素材视图切到章节视图后不挂载素材页；“返回剧集列表”沿用现有列表组件和选择状态，不引入素材页返回栈。匹配目标之后仅复用现有 `listStoryboardAssets` 路径；导航本身不读取音视频 URL、不创建媒体元素、不进行帧级滚动或写操作。

## Risks / Trade-offs

- [来源分组位置与原始章节响应错配] → 面板以同一个 ready 响应建立投影和按钮，且只在该来源读取世代有效时接受点击；目标页再次按 ID 校验。
- [新目录中目标身份消失或重复] → 不选默认首项、不触发素材 GET，说明无法确认，并保留目标供显式重读。
- [切换用户后迟到的章节成功/401] → 首帧隐藏和请求世代守卫；测试必须真实 settle 延迟 Promise 并在 `act` 后确认新用户状态不变。
- [StrictMode effect 探测导致重复 GET] → 在发送实际请求前检查本 effect 是否仍 active，并用真实请求计数用例确认目标目录只读一次。

## Migration Plan

此切片只改本地 React 导航与视图状态，不涉及数据库、服务端路由或部署迁移。若回归失败，回滚该切片的前端与测试改动即可；现有素材反查和普通章节浏览流程无需数据迁移。

## Open Questions

无。目标缺失时保留意图、唯一命中后消费、显式放弃时清理的规则已由本设计确定。
