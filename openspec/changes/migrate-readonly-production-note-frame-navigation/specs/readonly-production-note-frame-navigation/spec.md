# Spec Delta

## Purpose

让用户从本人当前已经核对的逐镜头制作记录显式定位同章分镜，连接备注和实际镜头。该能力保留既有续作导航及记录显示规则，以唯一原始身份和当前读取作用域保证安全，只操作本地焦点、滚动与反馈，不新增网络读取、制作写入或媒体播放。

## ADDED Requirements

### Requirement: 仅当前可信记录提供逐行定位

系统 SHALL 仅在现有逐镜头列表实际显示的行属于当前成功且核对完成的读取、媒体状态为 ready、原图快照可用、行 verified 且记录可识别时提供“定位到记录镜头 N”。系统 MUST 保持原有无保存记录隐藏逐行列表及旧孤立记录显示规则，不生成新的未保存镜头列表。定位不要求记录已认可；有效未标记、待修和待重新确认行均可定位。

#### Scenario: 可识别的已核对记录

- **WHEN** 当前列表行已核对，状态为未标记、待修、待重新确认或已认可
- **THEN** 系统提供带当前章节镜头序号的独立显式入口，打开或读取完成时不自动定位，原续作入口保持原行为

#### Scenario: 不可信或非当前行

- **WHEN** 读取中、摘要核对中、错误、空/无保存记录、旧孤立记录，或行未核对、记录不可识别、媒体失配/不可读、资产快照不可用
- **THEN** 系统不提供可操作的新定位入口，仍按既有规则显示记录和重读提示，不猜测对应镜头

### Requirement: 原始身份与同份读取绑定

系统 MUST 只接受同一当前 ready 读取中实际所属的记录行对象。定位所用非空原始 storyboard 身份 SHALL 在当前章节 first storyboard 引用和完整分镜素材响应中各自唯一；系统 MUST 先在完整素材响应按 raw ID 计数，再核对同章同剧集归属。显示序号仅由有效身份推导，不用响应 frame_index、历史序号、名称、正文或邻项兜底。

#### Scenario: 合格行映射到当前分镜

- **WHEN** 行属于当前读取，核对结果仍有效，其原始身份唯一且归属当前章节和剧集
- **THEN** 系统定位该唯一身份对应的当前分镜，父端独立复核实际行、读取结果和当前章节/素材身份，不只相信子端位置或当前性声明

#### Scenario: 数据歧义或对象替换

- **WHEN** 行对象不在该读取结果中、读取结果已替换，或身份缺失、重复、跨章、跨剧集、位置与当前唯一身份不一致
- **THEN** 系统拒绝定位，不回退首镜头或同文字镜头；当前点击失败时提供未定位说明，不报告成功

### Requirement: 显式本地定位和独立反馈

系统 SHALL 仅在用户点击后，对当前实际 DOM 目标同步聚焦并居中滚动，面板保持打开。系统 MUST 在聚焦前后核对读取、作用域、快照和 DOM；目标连接、可见、属于当前镜头列表且实际获得焦点后才滚动和报告成功。该定位反馈 SHALL 独立于续作、粗剪和素材导航反馈，镜头失焦包括进入其内部按钮时清除此反馈，不误清其他流程的新反馈。

#### Scenario: 键盘及重复点击

- **WHEN** 用户以点击或键盘触发合格入口，目标实际获得焦点
- **THEN** 系统即时滚动并提供文字位置反馈，保留记录面板；重复点击只重复本地操作，不增加 GET

#### Scenario: DOM 无效或聚焦失败

- **WHEN** 当前目标隐藏、inert、断开、不在当前容器、节点被替换或 focus 未实际转移
- **THEN** 系统不滚动、不报告成功，当前记录面板提供未定位说明；有效节点恢复后可再次显式定位

### Requirement: 首帧隔离和读取世代永久失效

系统 MUST 绑定当前用户、服务实例、剧集、章节对象、资产及媒体快照、面板打开世代、读取世代和同份读取结果/行对象。作用域变化首个可见提交即隐藏旧内容及入口；旧面板在 A→B→A 后仍永久失效，只有重新显式打开产生新读取。重读、关闭重开、切章、章节/原图显式重读、互斥面板切换、离开章节、任务页或退出均作废旧入口和回调，不自动补读或定位。

#### Scenario: 首个布局提交及 A 到 B 到 A

- **WHEN** 仅用户、services 或章节对象改变，随后回到旧对象
- **THEN** 旧记录入口首帧不可见且不复活、不自动 GET；旧定位回调不可操作当前视图，重新显式打开的新读取才可定位

#### Scenario: R1 旧失效回调晚于 R2 定位

- **WHEN** 同一打开作用域内重读产生 R2 并成功定位，之后实际回放 R1 的失效、定位或关闭回调
- **THEN** 系统按读取结果及 request generation 匹配，只作废对应读取；旧回调不能清 R2 反馈、移动焦点、关闭新面板或触发请求

### Requirement: 迟到响应与摘要不影响当前会话

系统 MUST 忽略已经失效的 GET 成功、401 和媒体摘要完成结果；旧响应不能恢复定位资格、清理新反馈或退出当前新会话。有效当前 401 与其他错误的原有处理行为保持，错误不冒充空记录。

#### Scenario: 退出后新用户与旧 Promise 完成

- **WHEN** 新用户已登录并打开自己的记录，旧用户请求或摘要实际完成，即使请求桩忽略 abort
- **THEN** 新用户、token、面板与定位保持当前，不被旧成功或401覆盖；自动证据必须实际 settle 原 Promise 并 await act

### Requirement: 保留读取及隔离验收边界

系统 MUST 保留既有十二业务接口、exact-five 来源复制、DTO、projection、媒体身份、services、demo/fixture样本及前十四批历史。打开/重读继续使用原个人记录 GET；新定位不新增 GET、接口、媒体元素/主动媒体读取或写入，不设置续作、认可、保存、取锁、播放、下载、生成或付费。既有安全原图展示仍可能读取 loopback PNG，不将新能力称为零媒体请求或旧 GET 数据库纯读取。

#### Scenario: 分层验证

- **WHEN** 在默认 demo 和隔离 fixture 验收定位
- **THEN** 点击前后业务 GET 增量为零，记录原有图片及实际访问路由；浏览器取消不冒充忽略 abort 的 Promise 证据，真实 FastAPI/数据库/Worker/R2/生产/付费均未运行，指定 Grillme 离线独立待办不由本 Sol 复核替代
