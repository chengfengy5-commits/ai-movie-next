# Spec Delta

## Purpose

让用户在本人当前章节的一份制作记录读取中，按既有投影状态快速筛出待处理镜头并查看数量，同时保留安全提示、旧记录和续作行为。该能力仅改变本地列表呈现，不改变状态核对、可信定位资格或任何后台数据。

## ADDED Requirements

### Requirement: 仅为现有当前记录列表提供七种筛选

系统 SHALL 仅在当前读取 ready、非无保存记录且当前镜头行非空时提供“全部”及已认可、待修、待重新确认、未标记、当前媒体暂不可核对、记录不可识别六种状态筛选。系统 MUST 使用既有当前状态投影，不从原始便签或认可布尔重新判定状态，不为本批生成未保存镜头的新列表。

#### Scenario: 原本可见的当前行显示筛选

- **WHEN** 本人的当前读取已完成，既有规则允许显示当前镜头列表
- **THEN** 七个选项可操作并默认全部，包含数量为零的状态选项

#### Scenario: 原本不显示当前列表的状态

- **WHEN** 面板读取中、媒体核对中、读取错误，或当前读取为无保存记录或当前镜头行为空
- **THEN** 不显示旧筛选、旧数量或新增列表，既有状态说明与独立旧记录仍按原规则显示

### Requirement: 数量与过滤来自同一完整当前列表

系统 SHALL 按完整当前镜头列表的投影状态计算每种数量和全部数量，排除独立旧记录；选择状态后数量不得改为筛选结果的局部统计。筛选结果 SHALL 保留原顺序、原镜头位置和原行对象，不改变行的核验结果或定位资格。

#### Scenario: 筛选待修且保留原位置

- **WHEN** 用户从包含多种状态的当前列表选择待修
- **THEN** 只显示原待修行，其原镜头序号和相对顺序保持，所有选项数量仍来自完整当前列表

#### Scenario: 历史认可不计入当前认可

- **WHEN** 存在媒体版本变化后已投影为待重新确认的记录、不可核对记录或独立历史认可记录
- **THEN** 数量和结果遵从当前投影，不能将它们计入当前已认可，旧记录不计入任何当前状态数量

### Requirement: 零命中与全局安全信息分离

系统 SHALL 将零命中说明限定为“这份当前镜头记录中没有该状态”，并提供显式恢复全部的操作；不得将其显示为无保存记录、服务端空数据或整部剧集不存在该状态。全局媒体/身份警告、无法对应当前镜头的旧记录和续作区域 MUST 独立于筛选结果持续显示。

#### Scenario: 当前读取没有已认可行

- **WHEN** 用户选择数量为零的已认可状态
- **THEN** 显示本份当前列表零命中的说明与回到全部入口，全局警告、旧记录和原续作区域仍可见

### Requirement: 筛选只做本地呈现

系统 MUST 将筛选作为当前面板的临时本地状态，不发起额外业务请求、媒体摘要、媒体读取、自动重读或导航，不写 URL、持久存储或跨用户缓存。系统 MUST 保留既有读取身份登记、世代、失效水位及父端定位校验，不能以筛选触发它们的失效通知。

#### Scenario: 多次改变筛选和重复点击

- **WHEN** 用户在同一当前读取中切换状态、返回全部或再次点击当前状态
- **THEN** GET、摘要捕获和媒体操作数量不因此增加，读取身份不改变，也不会自动聚焦镜头

### Requirement: 每次新读取默认全部且拒绝旧操作

筛选选择 SHALL 绑定生成它的当前 readout 和读取凭据。重读、关闭重开、用户/服务/章节对象或既有 scope 变化时，系统 MUST 在首个可见提交隐藏旧筛选与内容，并使新的有效读取默认全部；旧回调、旧请求成功/401或旧摘要完成不得改变新读取或新会话。A→B→A 不得复活失效面板或其旧选择。

#### Scenario: 重读完成后拒绝旧筛选回调

- **WHEN** 用户已在 R1 选择状态，显式重读获得 R2 后实际回放 R1 筛选回调
- **THEN** R2 仍默认全部，旧回调不能改变其数量或可见行，当前用户身份不受影响

#### Scenario: 新 scope 首帧与迟到结果

- **WHEN** 当前面板的用户、服务或章节对象改变，之后旧 GET 成功/401或旧摘要真正完成
- **THEN** 第一父布局提交已看不到旧筛选、数量和记录，迟到结果无效；返回旧 scope 不自动重开，显式重开取得新读取并默认全部

### Requirement: 原定位与续作能力保持

系统 SHALL 对筛选后可见的合法原行继续提供既有逐行定位，不降低现有可信身份、媒体核对或记录可识别要求；未通过核对的行不得新增定位入口。原续作提示与入口 MUST 使用完整当前读取，不能按筛选结果重新计算或消失。鼠标或键盘操作筛选造成的正常失焦 SHALL 沿用既有反馈清理，不增加父端读取失效回调。

#### Scenario: 筛选后定位原可信记录

- **WHEN** 用户筛出待修或待重新确认的可信行并点击其原定位入口
- **THEN** 仍用同份完整读取中的实际行进行现有校验和本地定位，无附加读取，独立续作行为保持

### Requirement: 可访问操作与隔离边界保持

筛选 SHALL 有明确的可访问名称、选中状态与状态数量，支持键盘操作，在桌面及 390px 视口可阅读且不引入水平溢出。该能力 MUST 限于隔离前端，保持十二种业务接口、exact-five 来源复制、现有样例与媒体链路；不增加编辑、认可、保存、播放或真实服务调用。客户端只读不得被描述为旧 GET 在真实数据库中无维护副作用。

#### Scenario: 原样 demo 与隔离 API 分层验收

- **WHEN** 对原样 demo 和现有隔离 fixture 进行筛选验收
- **THEN** 仅以它们实际具备的状态记录浏览器结果，完整六状态和忽略 abort 的迟到 Promise 由自动化分别举证，不扩样例或冒称真实后端回归
