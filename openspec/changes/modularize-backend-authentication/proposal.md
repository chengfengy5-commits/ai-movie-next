# Proposal

## Why

新后端已提供个人粗剪、个人制作记录与真实剧集访问策略，但统一工厂的身份仍由调用方注入，尚未迁移旧系统的登录、会话、会员校验及邮箱验证码闭环。本批迁移完整认证业务，使隔离环境可以用真实密码哈希、JWT 和 SQL 会话访问既有四个业务方法，并保留固定来源的兼容行为。

这是后端模块化迁移，不是生产认证上线。JWT 密钥、数据库 Session 工厂与邮件发送供应商由调用方显式配置；本批不读取环境或秘密，不连接生产数据库，不发送真实邮件。

## What Changes

- 新增独立 `authentication` 模块，完整实现注册、登录、本人信息、会话列表、会话撤销、修改密码、忘记密码、重置密码、本人积分、发送验证码与校验验证码共 11 个认证方法。
- 统一 `create_app` 注册 11 个认证方法及既有粗剪、制作记录 GET/PUT，共 15 个方法；关闭自动文档端点。保留显式 `resolve_actor` 的优先级，未提供它时可由已配置认证运行时提供真实 JWT 身份与会员校验；依赖不齐全时返回 503，不创建 Session。
- 按领域规则、应用用例、SQLAlchemy 最小表投影、密码/JWT 适配器及 HTTP 边界组织代码。保留会话维护的实际提交顺序、旧密码规则与响应、验证码消费差异、重置密码不撤销会话等现有行为，不暗中增加新安全政策。
- 使用显式端口和不读取环境的进程内适配器提供三条既有限流与验证码存储；邮件发送仅接入显式供应商端口，不迁移 SMTP 账号轮发、配置管理或真实发送链。
- 为真实临时 SQLite 持久化、提交失败、JWT/密码、完整 HTTP 契约及冷导入增加测试。根代理另行执行真实 loopback 和既有 TypeScript 用户契约解析，区分源码复核、本地测试及生产未验证边界。

## Capabilities

### New Capabilities

- `backend-authentication`: 模块化完整认证、邮箱验证码、会话和会员身份边界，并向既有四个业务方法提供可配置的真实认证接线。

### Modified Capabilities

无。当前主规格库存为空；既有业务模块的冻结行为通过本次集成契约和回归测试保护。

## Impact

- 仅允许修改统一工厂、后端依赖声明及四个既有工厂边界测试，共六条旧代码路径；其余 169 条既有代码/配置/参考/验收路径与 147 个历史产物保持冻结。既有粗剪、制作记录、访问策略、前端、fixture、样本和依赖缓存不改。
- 新增 `backend/src/haoai_backend/authentication/` 下的完整模块及专用测试，精确文件名单在 design 中定义。邮件供应商、验证码生成、时钟和 JWT 配置显式注入，生产代码不含测试身份、默认允许策略、Engine 创建、schema 初始化或旧应用导入。
- 允许事后向四份既有说明追加本批内容并新增两份说明；所有旧正文保持。独立指定 GPT-5.6 Sol/xhigh Grillme 审查仍单独待办，本次内部复核与根验收不能替代它。
